# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Research preprint: which reactive Kubernetes autoscaling signal (queue depth, running requests, KV-cache usage, TTFT, QPS, combined) to use for vLLM inference. Plain Python scripts plus a LaTeX paper. There is no package, build system, test suite or linter.

The evidence comes from three tiers, and they must never be mixed up in prose or tables:

1. **Measured**: real vLLM on an NVIDIA T4 (Kaggle/Colab), single replica, rate sweep 1–32 rps. Produced by `profile_vllm.py` (see `KAGGLE_RUNBOOK.md`), stored in `data/results_run{1,2,3}/`. Provenance and known caveats are in `data/PROVENANCE.md`.
2. **Emulated cluster**: local kind cluster running `llm-d-inference-sim` (a vLLM emulator calibrated to the T4 data), Prometheus, and KEDA ScaledObjects. Raw trial logs go in `runs/`.
3. **Simulated**: discrete-event simulator `sim/autoscale_sim.py`, used for sweeps too slow to run on kind. Every simulator result must be labelled SIMULATED.

## Commands

Use the venv: `.venv/bin/python` (deps: `aiohttp numpy scipy matplotlib`).

# Single-replica emulator validation against the T4 sweep

## Architecture notes

- **Policies are defined twice and must stay in sync**: as KEDA ScaledObjects in `cluster/policies/*.yaml` (generated by `cluster/policies/generate.py`; rerun it after edits) and as `POLICIES` in `sim/autoscale_sim.py`. YAML placeholders `MAX_REPLICAS`, `STABILIZATION`, `QUEUE_T` are substituted by `experiments/run_trial.py` at apply time. Thresholds labelled "80% of measured capacity" are derived from T4 data at 6.4 req/s.
- **Load schedules** (`step`, `ramp`, `steady`, as `rate:duration` segments) are duplicated in `experiments/run_trial.py` and `sim/autoscale_sim.py` `LOADS`. `cluster/loadgen.py` takes the same segment syntax and reproduces `profile_vllm.py`'s request mix (lognormal 256/128 tokens, same seed).
- **Simulator calibration**: constants at the top of `sim/autoscale_sim.py` (`TPOT_TABLE`, `G`, `TPOT_SCALE`, prefill fit, `KV_TOKENS`) come from the T4 runs; `G` and `TPOT_SCALE` are fit by `sim/calibrate.py` (result in `sim/calibration_result.txt`). `PRESTOP` matches `cluster/vllm-sim.yaml`. `DEFAULT_CFG` holds the baseline knobs that `sweep.py` and `followup.py` vary one at a time.
- **Trial output layout**: `runs/main/<load>/<policy>/trial<k>/` with `requests.jsonl`, `pods.jsonl`, `prometheus.json`, `config.json`, `done.json`. The campaign snapshots the exact emulator and policy configs into `runs/main/config_snapshot/`.
- **Pod-seconds window**: kind trials are polled over schedule + 30 s, and the simulator summarizes over the same window so kind and sim numbers are comparable (`pod_seconds_tail120` adds the scale-down tail).
- **Known emulator/vLLM mismatch**: the emulator's TTFT metric excludes queueing time, but vLLM's (and the simulator's) includes it. This affects only the `ttft` policy on kind; see `data/PROVENANCE.md`.
- `paper/main.tex` `\input`s the generated `fidelity_table.tex` and `routing_table.tex`; figures live in `paper/figures/`. Numbers quoted in the paper should trace back to `analysis/results/*.txt`.

## Research integrity rules

- Report only real runs. Do not invent, smooth or extrapolate numbers. Label every number as measured (T4), emulated (kind) or simulated.
- Keep raw logs in `runs/` and `data/`, including failed runs (for example `runs/demo_queue_FAILED_fdlimit.jsonl`). When a config changes, create a new versioned directory (`emuval_v1` → `v2`, `sweep_v1` → `v2`) instead of overwriting the old one.
- `scripts/autopush.sh` commits and pushes `runs/main` periodically while a campaign runs.
